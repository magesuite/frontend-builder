# SSL certificates — per-machine setup.
browserSync proxies https://magesuite.me, so it must also serve over HTTPS — otherwise the browser blocks mixed-content requests and assets fail to load. 
A self-signed certificate is not enough. Browsers reject it with ERR_CERT_AUTHORITY_INVALID. 
mkcert solves this by generating a certificate signed by a locally-trusted CA (Certificate Authority) that it installs into the system and browser trust stores.

Certificate generation is automated — yarn serve runs mkcert -install and generates localhost.pem + localhost-key.pem in the theme root directory automatically on every start, covering both localhost and the machine's current local IP address.

# Security considerations
mkcert works by installing a local Certificate Authority (CA) into the system trust store. 
This means any certificate generated by mkcert will be automatically trusted by the browser — which is exactly what makes it convenient. 
However, it is important to understand what that trust actually covers.

The certificates generated for localhost and the local IP address are harmless on their own — they are useless outside the local machine. 
The real scope of trust comes from the CA itself. Its private key is stored at the path returned by mkcert -CAROOT (typically ~/Library/Application Support/mkcert/ on macOS). 
If someone obtained that file, they could generate trusted certificates for any domain and the machine would accept them silently, including sensitive sites like banking or email.

In practice the risk is low — the private key never leaves the machine and is protected by the macOS user account permissions. 
mkcert is a widely used and well-regarded tool in the developer community for exactly this use case. 
Company Macs used as personal devices carry the same risk profile as any other development tool installed on that machine and are considered acceptable.

Best practices:

- Never share or commit the mkcert -CAROOT directory contents.
- If your machine is compromised, run mkcert -uninstall to remove the CA from the system trust store.
- Do not install the mkcert root CA certificate on phones, tablets, or other shared devices — only developer machines where the full mkcert toolchain is installed and controlled by the same person. 
  On a developer machine, the CA private key and the trust store are both under the same person's control. 
  On a phone or tablet, you would be extending trust to a key that lives on a separate machine — if that machine is ever compromised, the phone would silently trust malicious certificates with no way to detect it.

# Prerequisites
The only prerequisite is installing mkcert once per machine.

# Install mkcert (macOS)
brew install nss           # required for Firefox support
brew install mkcert

mkcert — a tool for generating locally-trusted SSL certificates. Instead of using a self-signed certificate (which browsers reject), it creates its own local Certificate Authority and installs it into the system trust store, so any certificate it generates is automatically trusted by the browser.

nss (Network Security Services) — a set of libraries used by Firefox to manage its own certificate store, separate from the system keychain. Installing nss before running mkcert -install allows mkcert to register the local CA in Firefox as well, otherwise Firefox would still show the security warning even after other browsers trust the certificate.

After that, yarn serve handles everything else. Both .pem files are machine-specific and should be added to .gitignore.
